Developer documentation

Understand the flow before you deploy.

ZervxHub is source code, not a hosted service. These guides describe the current implementation and the configuration an authorized project owner must provide.

Never put a private credential in a Roblox client or public repository.

Keep Worker secrets and developer API keys in the server or trusted host that needs them. Never share raw license keys in public support requests.

Developer onboarding

  1. Review the deployment checklist and confirm you control the Roblox experience and Discord server.
  2. Request onboarding through the project repository. Developer accounts are currently provisioned by an administrator; there is no self-service signup or dashboard.
  3. An administrator creates the developer account and provides a developer API key once. Store it in a password manager and only send it from your trusted backend.
  4. Register your Roblox Universe ID and a display name using the developer API. The game stays pending until an administrator reviews and approves it.
  5. Connect your Discord guild with administrator credentials, then configure the bot. The bot uses its own service token and resolves access through the guild-to-developer integration.

Use the exact API routes and environment names in the repository documentation. Do not copy real credentials into tickets, screenshots, scripts, or chat messages.

Administrators should follow the complete onboarding and account lifecycle guide.

Discord bot

  • Create a Discord application and invite the bot with the application-command scope.
  • Set the bot token, application ID, configured guild ID, Worker URL, and bot service token in the hosting provider's secret variables.
  • Set the matching bot API token as a Worker secret. Do not use the Worker admin token as the bot token.
  • /getkey returns a key privately. /revoke-key requires Manage Server permission.

Commands require an active integration and approved game. Details are in the bot source and setup files.

Roblox server integration

  1. Install roblox/ZervxHubKeyServer.server.lua as a Script in ServerScriptService.
  2. Replace the Worker URL placeholder with the URL of your own configured deployment. Do not put an admin, bot, or developer token in this script.
  3. Enable HTTP requests in Roblox Studio for the experience and verify that the Worker allows the exact Universe ID.
  4. Install roblox/ZervxHubKeyPrompt.client.lua as a LocalScript in StarterPlayerScripts.
  5. Gate protected server-side actions on the server-controlled ZervxHubAuthorized player attribute. A client interface is not an authorization boundary.

Roblox Studio testing has not been performed as part of this repository verification. Follow the Roblox server integration guide and test in a private experience you control.

License lifecycle

The current implementation issues active 24-hour keys, validates expiry and approved-universe ownership on the server, and allows authorized revocation. A distinct activation flow, subscription entitlement, payment checkout, and customer portal do not exist. See current pricing and access status.

Security and operational boundaries

  • New credentials are HMAC-SHA-256 hashed with a Worker pepper before storage.
  • API access is scoped to a developer, approved game, and configured Discord guild.
  • Rate limits in the Worker are per isolate; production operators must configure edge-level limits as described in deployment guidance.
  • Use a staging Worker and local D1 for testing. Review migrations before manually applying them to a remote database.
