# Security Policy

## Supported Versions

Security fixes are developed against the actively maintained ZervxHub development branch. Do not assume older snapshots, archived ZIP files, or unmerged branches receive security updates.

## Reporting a Vulnerability

Please do **not** report suspected vulnerabilities in public GitHub issues, discussions, pull requests, or Discord channels.

Use GitHub's **Report a vulnerability** option in the repository's Security tab to send a private vulnerability report. Include:
- A clear description of the affected component and potential impact.
- Reproduction steps or a minimal proof of concept, where safe.
- The affected commit, branch, endpoint, or version.
- Any suggested mitigation.

If private vulnerability reporting is unavailable, contact the repository maintainer through the GitHub profile without publishing exploit details.

## What to Expect

Reports will be reviewed as soon as practical. Please allow time for validation, remediation, and coordinated disclosure before sharing details publicly.

Do not include real user data, production credentials, API keys, session cookies, or other secrets in a report. Revoke and rotate any credential that may have been exposed.

## Scope and Safety

Testing must be limited to systems and accounts you own or have explicit permission to assess. Do not access, modify, or delete other users' data, disrupt services, or perform destructive testing.
